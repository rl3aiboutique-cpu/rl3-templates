## 1. Goal

Author a single Copier template named `baseline` that renders into any new RL3 repository:

1. A local pre-commit configuration with modern, fast tooling.
2. Claude Code agent guardrails (`.claude/settings.json`) that block destructive Bash commands, edits to generated files, and direct pushes to protected branches.
3. Pre-push hooks that enforce branch naming and routing.
4. A drift-detection workflow that opens a weekly PR with template updates.
5. Standalone helper scripts under `scripts/hooks/` — no external CLI dependency.

After Phase 1 lands, every new RL3 repository will start from this template and stay aligned via `copier update`.

## 2. Non-goals (explicitly out of Phase 1)

- **No `codi` coupling.** No `.codi/` directory, no skill tracker / observer hooks, no `_run-node` shim. Phase 3 will add a `enable_codi` flag.
- **No `rl3-ci` workflow callers.** No `ci.yml` rendered. No `_ops-pr-policy.yml` or `_ops-hotfix-backmerge.yml`. Phase 2 will add a `enable_rl3_ci` flag.
- **No retrofit of existing repos.** The 7 RL3 repositories (capellai-ai-crm, sapphira-clinic, rl3-website, code-graph-rag, codi, codi-brain, devloop, rl3-infra-vps) stay untouched in Phase 1.
- **No GitHub remote push.** The repository stays local until explicit go-ahead.

## 3. Threat model (summary — full rationale in design discussion)

Phase 1 hooks defend against:

- **`--no-verify` bypass by AI agent** — blocked at `.claude/settings.json` deny-list.
- **`git push --force` to shared branches** — blocked at agent layer + branch protection (Phase 2 GitHub setup script).
- **Direct push to `master` / `develop`** — blocked at pre-push hook + agent deny-list.
- **Secrets in MCP / agent config files** (Sandworm-mode mitigation) — `scripts/hooks/scan-agent-configs.sh` scans `.claude/`, `.cursor/`, `.codi/mcp-servers/` even when gitignored.
- **AI slop**: oversize files, debug statements, orphan TODOs, `NotImplementedError` stubs, `Co-Authored-By: Claude` trailers.
- **Edits to generated files**: `routeTree.gen.ts`, `frontend/src/client/`, `*.lock`, `.copier-answers.yml`.

## 5. The 14 non-negotiables

1. **Pre-commit framework** as the substrate. Husky carve-out only for `codi` itself.
2. **Block markers** (`# rl3-templates: managed BEGIN/END`) delimit autogenerated content.
3. **`--no-verify` is forbidden for the agent**; CI is the authoritative gate.
4. **`--force-with-lease` is the only allowed force push**, and only on non-protected branches.
5. **`Co-Authored-By: Claude` is forbidden** at commit-msg hook + content scan.
6. **MCP / agent config files are scanned for secrets** even when gitignored.
7. **700-line cap** for code files; no cap for docs.
8. **TODOs require ticket reference** (`TODO(ABC-123)`); orphan TODOs blocked.
9. **Generated files cannot be hand-edited**: `routeTree.gen.ts`, `frontend/src/client/**`, `*_pb2.py`, `*.lock`, `.copier-answers.yml`.
10. **Pre-push tier enabled by default** (pip-audit + pytest cov), gated by flag.
11. **No direct push to `master` or `develop`.** Three layers: pre-push + agent + branch protection.
12. **Branch naming mandatory**: `<prefix>/<git-username>/<slug>` where prefix ∈ {feature, bugfix, chore, release, hotfix}. Optional `<TICKET-ID>-` infix in the slug. The `<git-username>` segment is derived from `git config user.name` (lowercased, kebab) — enforces ownership.
13. **PR routing matrix enforced in CI** (Phase 2).
14. **Hotfixes are not a bypass** — permitted route with own SLA, mandatory back-merge.

## 6. Branching policy (rendered into every consumer's CLAUDE.md)

Branch shape: `<prefix>/<git-username>/<slug>` (with optional `<TICKET-ID>-` infix).

| Source | Target | Reviewers | Use case |
|---|---|---|---|
| `feature/<user>/<slug>` | develop | 1 | New feature |
| `bugfix/<user>/<slug>` | develop | 1 | Non-urgent bug fix |
| `chore/<user>/<slug>` | develop | 1 | Tooling, deps, docs |
| `release/<user>/v<x.y.z>` | master | 2 | Release PR |
| `develop` | master | 2 | Integration PR |
| `hotfix/<user>/<slug>` | master | 1 (fast) | Production fix |
| `hotfix/<user>/<slug>` (auto-opened) | develop | 1 | Mandatory back-merge |

Examples:

- `feature/lehidalgo/add-csv-export`
- `feature/lehidalgo/RL3-142-add-csv-export`
- `hotfix/jdoe/CBP-99-fix-payment`

Branch sources:

- `feature|bugfix|chore|release` — branched from `origin/develop`.
- `hotfix` — branched from `origin/master`.

Emergency override: only two named human admins, configured server-side. Never the agent.
